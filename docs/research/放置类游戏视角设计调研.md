# 放置类/管理类游戏视角设计调研报告

*生成: 2026-07-09 | 来源: 20+ 网络来源 | 用途: XianxiaSect 宗门地图视角设计参考*

---

## 一、执行摘要

放置类和管理类游戏的视角设计并非纯视觉选择，而是**核心玩法系统的组成部分**。调研覆盖了从经典开罗像素到现代 3D 城市建造的完整谱系，主要发现：

1. **斜45°伪3D（Isometric/Dimetric）** 是放置经营类游戏最主流的视角选择 — 兼顾信息密度和视觉深度
2. **正交投影（Orthographic）** 远优于透视投影 — 消除透视变形，确保所有物体在屏幕上同等大小，信息传递不受距离干扰
3. **移动端视角已高度成熟** — 单指拖拽平移 + 双指捏合缩放为事实标准，2-4 级信息层级缩放是 SLG 标配
4. **固定角度 vs 自由旋转** 是核心设计决策 — 固定角度牺牲灵活性换取阅读一致性，自由旋转反之
5. **宗门视角选择应优先考虑玩法需求**（弟子/建筑/地图的信息密度）而非视觉华丽度

## 二、主流视角分类学

### 2.1 纯俯视（Top-Down 2D）

| 维度 | 说明 |
|------|------|
| **视角** | 摄像机正对地面，Y轴垂直向下 |
| **投影** | 正交投影 |
| **代表游戏** | 开罗全系列、原版 SimCity（1989）、RimWorld |
| **优点** | 方向感清晰（东西南北）、信息密度极高、制作成本最低、无遮挡问题 |
| **缺点** | 缺乏立体感、建筑只露屋顶、视觉层次单一 |
| **适合** | 系统深度 > 视觉沉浸的数值驱动游戏 |

**开罗游戏的视角哲学**（Kairosoft）：
- 全部采用像素 + 45°俯视（正俯视或略倾斜）
- 支持放大画面操作，但**不旋转**
- 像素风格不是怀旧，而是**主动选择的克制美学** — 每个建筑、员工、动线清晰可辨，无华丽特效遮挡视线
- 开罗游戏设计者刻意留出"呼吸感"：像素小人走路慢但没人觉得卡顿，快节奏时代获得可控沉浸

**RimWorld 的设计决策**：
- 使用 Unity 3D 引擎但**强制锁定俯视正交视角**
- 开发者在 Steam 讨论中直言：*"Had Tynan decided to invest the time into a 3D RimWorld, there would have been a very real danger of it never getting finished"* — 2D 视角是**保证项目完成度的务实选择**
- 固定视角让模组社区更容易创作内容（2D sprite 比 3D model 简单太多）

### 2.2 斜45°伪3D（Isometric / Dimetric / Trimetric）

这是放置经营类**最主流的视角类型**。需注意技术细分：

| 投影类型 | 三轴比例 | 代表游戏 |
|----------|---------|---------|
| **Isometric**（正等测） | 三轴等比例缩短，120°夹角 | Zaxxon, Q*Bert |
| **Dimetric**（正二测） | 两轴相等，一轴略短 | **SimCity 2000/3000**（实际是 dimetric），**Clash of Clans**（4:3 oblique） |
| **Trimetric**（正三测） | 三轴均不相等 | **SimCity 4** |

**关键技术参数**：

| 游戏 | 投影类型 | 瓦片比例 | 摄像机倾角 |
|------|---------|---------|-----------|
| Clash of Clans | 斜角投影 4:3 Oblique | 64×48 (4:3) | ~47.5° |
| 标准 Isometric | 正等测 | 64×32 (2:1) | ~30° |
| Factorio | 类 Isometric | ~38-45° 实际倾角 |
| 传统 RTS | Dimetric | 2:1 或 4:3 |

**Clash of Clans 的核心设计逻辑**（来源：GameDev StackExchange）：
- 采用 4:3 瓦片比（64×48），**非正等测 2:1**
- 原因：更陡的俯角 → 建筑遮挡更少 → 每一块地都清晰可见、可建造
- 对基地建造游戏至关重要：玩家需要看到每一个格子
- 坐标转换公式：
```
// 网格 → 屏幕
int ox = (ix - iy) * Tile.width / 2;
int oy = (ix + iy) * Tile.height / 2;

// 屏幕 → 网格（砖块拾取）
int ix = (int)(wx / (Tile.width / 2f) + wy / (Tile.height / 2f)) / 2;
int iy = (int)(wy / (Tile.height / 2f) - wx / (Tile.width / 2f)) / 2;
```

**为什么 SimCity 系列长期坚持固定角度**（来源：MobyGames / Strategy Wiki）：
- SimCity 2000 引入斜角视角至 SimCity 4，**20年从未真正 isometric** — SC2000/3000 是 dimetric，SC4 是 trimetric
- 固定角度是**刻意的设计选择，不是技术限制**
- 同时看到城市布局（俯视信息）和建筑立面（个性特征），纯俯视和第一人称都无法做到
- 直到 2013 年重启作才放弃固定角度，改用真 3D 自由旋转

### 2.3 2.5D 三渲二（3D Model → 2D Sprite）

| 维度 | 说明 |
|------|------|
| **方法** | 3D 建模在固定角度渲染为 2D 精灵图 |
| **代表游戏** | Factorio、Clash of Clans（现代版） |
| **优点** | 享受 3D 建模管线便利 + 2D 渲染性能 + 固定角度一致性 |
| **缺点** | 每旋转一次需要重新构图（Factorio FFF #295: *"every rotation is a new model/composition"*） |

**Factorio 的做法**（来源：Factorio Forums / FFF #295）：
- 使用 Blender 建模后渲染为 2D sprite
- 所有 sprite 从固定 ~38-45° 角渲染
- **每个旋转方向是独立构图**（不是简单旋转 sprite）
- 频繁视觉"作弊"：拉平建筑高度避免遮挡传送带、炼油厂用四套独立模型而不是一组旋转
- 核心原则：**可读性 > 视觉真实度**

### 2.4 3D 自由视角

| 维度 | 说明 |
|------|------|
| **方法** | 真 3D 场景 + 自由摄像机 |
| **代表游戏** | Cities: Skylines、SimCity 2013、Two Point Hospital |
| **优点** | 沉浸感最强、建筑细节丰富、可旋转/俯仰 |
| **缺点** | 开发成本高、遮挡问题需要额外解决、移动端性能消耗大 |

**Two Point Hospital 的 3D 等距视角**：
- 使用 3D 场景 + 锁定等距角度（可旋转）
- 结合了 3D 的视觉丰富度和等距的清晰度
- 建筑墙壁在摄像机靠近时变为透明

### 2.5 视角选择决策矩阵

| 决策维度 | Top-Down 2D | Isometric/Dimetric | 2.5D 三渲二 | 3D 自由视角 |
|----------|------------|-------------------|-------------|-------------|
| 信息密度 | ★★★★★ | ★★★★☆ | ★★★★☆ | ★★★☆☆ |
| 视觉沉浸 | ★★☆☆☆ | ★★★☆☆ | ★★★★☆ | ★★★★★ |
| 开发成本 | ★★★★★ | ★★★★☆ | ★★★☆☆ | ★★☆☆☆ |
| 移动端性能 | ★★★★★ | ★★★★★ | ★★★★☆ | ★★★☆☆ |
| 遮挡问题 | 无 | 中等 | 可管理 | 严重 |
| 模组友好度 | ★★★★★ | ★★★★☆ | ★★★☆☆ | ★★☆☆☆ |
| 典型类型 | 数值经营 | 基地建造/RTS | 工厂模拟 | 现代城市建造 |

## 三、代表性游戏深度分析

### 3.1 Clash of Clans（Supercell）— 移动端经营建造的标杆

**视角规格**：
- **4:3 斜角 Oblique 投影**（非正等测）
- 64×48 瓦片尺寸
- 正交摄像机，俯角约 47.5°
- **不旋转、不平移**（全地图在一屏内一览）

**设计逻辑**：
- 更陡的俯角 → 减少建筑相互遮挡 → 基地建造游戏的核心需求
- 固定屏幕（无滚屏）→ 所有内容一屏展示 → 简化触控交互
- 现代版本使用 3D 建模 + 固定角度渲染 → 兼顾视觉质量和性能
- 与 Rise of Kingdoms 形成对比：RoK 强调"无极缩放"作为差异化卖点

### 3.2 Factorio（Wube Software）— 工厂模拟的视角圣经

**视角规格**：
- 固定等距视角（实际 ~38-45°）
- 正交投影
- **不可旋转**
- 摄像机锁定在玩家角色位置
- 可缩放（从近景到鸟瞰）

**设计原则**：
1. **可读性优先** — 每个实体在典型缩放级别下必须清晰可辨
2. **视觉作弊常态化** — 为可读性可以牺牲视觉一致性
3. **每旋转=重新构图** — 不同方向的建筑工事需要重新建模/合成
4. **无视角动态** — 不要用摄像机运动干扰玩家的规划思维

**历史教训**：
- 社区讨论"为什么不做 3D"（来源：Factorio Forums）：
  - 3D 中建筑无论从哪个角度看总会挡住视线
  - 同类型 3D 工厂游戏（Satisfactory、DSP）的硬件需求高得多
  - 固定 2D 视角让百万吨级的工厂规模成为可能

### 3.3 Dyson Sphere Program（Youthcat Studio）— 3D 工厂的视角创新

**视角规格**：
- 第三人称（跟随机甲）+ **神模式（God Mode）** 自由摄像机
- 可从地面无缝缩放到星际视图
- 支持球形行星表面建造

**设计亮点**（来源：Goonhammer 三厂对比）：
- "**Best of both worlds**" — 保留 3D 空间感和视觉效果，同时通过 God Mode 解决 3D 建造操作的精确性问题
- 球形表面带来 Factorio 无限平面所没有的**空间约束设计挑战**
- TV Tropes 描述："Factorio 的规划便利 + Satisfactory 的 3D 视觉效果之间的黄金妥协"

**对比三厂视角差异**：

| 维度 | Factorio | DSP | Satisfactory |
|------|----------|-----|-------------|
| 摄像机 | 2D 固定等距 | 第三人称 + God Mode | 第一人称 |
| 核心压力 | 虫群攻击 | 资源跨界管理 | 探索 + 效率 |
| 空间约束 | 无限平面 | 球形星球（有限） | 3D 地形 |
| 建造感受 | 高效精确 | 灵活宏大规模 | 费力但沉浸 |

### 3.4 中国 SLG 手游（率土之滨 / 三国志战略版）— 4E 战略信息层级

**视角设计方法论**（来源：网易 IXDC 工作坊）：
- **4E 战略信息模型**，将视角和地图信息分为 4 层：

| 层级 | 名称 | 信息内容 | 摄像机距离 |
|------|------|---------|-----------|
| M1 | 战术操作层 | 单支部队状态、行军、驻守 | 最近 |
| M2 | 战术分析层 | 战斗单位群位置、行动轨迹、交战热点 | 较近 |
| M3 | 战略分析层 | 军团分布、进攻趋势、战线推进 | 较远 |
| M4 | 战略观察层 | 势力面积、全局态势 | 最远（鸟瞰） |

**瓦片系统差异**：
- **率土之滨**：斜 45° 正方形网格，8 方向邻接，225 万格无缝沙盘
- **三国志战略版**：交错正方形网格（类似《三国志11》），每块地与周围 6 块地连接，带来更柔和自然的视觉流动

**核心设计要点**：
- 无级缩放支持 M1-M4 无缝过渡
- 宏观战斗表现（"万人在线"）优于微观战斗细节
- **制图综合理论** + **军事地图理论**应用于游戏地图设计

### 3.5 Cities: Skylines / SimCity 系列 — 城市建造的视角进化

| 时代 | 游戏 | 视角 | 创新 |
|------|------|------|------|
| 1989 | SimCity | 纯俯视 2D | 开创城市建造类型 |
| 1993 | SimCity 2000 | Dimetric | 引入斜角伪 3D + 地形高度 |
| 2003 | SimCity 4 | Trimetric | 混合 2D/3D 渲染 + 锁定视角 |
| 2013 | SimCity (2013) | 真 3D | 首次支持自由旋转 |
| 2015 | Cities: Skylines | 真 3D + Mod | 自由摄像机 + 第一人称步行模式 |

**关键洞察**：从固定等距到自由 3D 的进化花了 20 年，且不是简单的"进步"——每个阶段都有明确的**权衡逻辑**。

## 四、移动端视角交互模式

### 4.1 手势标准

| 手势 | 功能 | 说明 |
|------|------|------|
| **单指拖拽** | 平移/滚屏 | 事实标准，直觉化操作 |
| **双指捏合** | 缩放 | 像素级精确，与平移无缝衔接 |
| **双指旋转** | 视角旋转 | 高级功能，非所有游戏必备 |
| **双击** | 聚焦/回正 | 快速回到主要目标/初始视角 |
| **长按 + 拖拽** | 框选 | 用于批量操作（建造/选取） |

**原则**（来源：SunStrike Studios 移动游戏设计手册）：
- 将操作动词映射到**最少的手势数量**
- 每个手势必须通过引导让玩家一目了然
- 保持屏幕中心区域清洁，让玩家看到操作结果
- 释放双指后应平滑过渡到单指平移（无状态突变）

### 4.2 速度缩放联动

```csharp
// 缩小时平移速度应更快，放大时更慢
panSpeed = basePanSpeed * (currentZoom / maxZoom);
```

### 4.3 缩放级别设计

| 缩放级别 | 用途 | 显示内容 |
|----------|------|---------|
| **特写** | 查看/操作单个对象 | 弟子详情、建筑交互 |
| **标准** | 局部操作 | 宗门区域、建筑布局、人物移动 |
| **缩略** | 全局概览 | 整个宗门地图、资源分布 |
| **鸟瞰**（可选） | 战略视图 | 世界地图、势力范围 |

**关键原则：每级缩放必须有明确的信息设计** — 不是简单放大缩小，而是**切换信息密度和呈现方式**。

### 4.4 边界与约束

- **软边界**：平移时在边缘出现弹性阻力感（而非硬停）
- **硬边界**：锁定 camera rig 位置，永不露出世界外空白
- **缩放范围**：clamp 在 [minZoom, maxZoom]，避免穿透地面（最小）或世界失去可读性（最大）

## 五、技术实现模式

### 5.1 Camera Rig 模式（行业标准）

```
CameraRig (Empty GameObject)
  └─ Camera (子物体，有 offset)
```

- **Rig** 处理位置和旋转（世界空间）
- **Camera** 处理 zoom distance 和 pitch（局部偏移）
- 移动 Rig = 平移，移动 Camera 相对 Rig = 缩放
- **关键**：策略/经营类游戏移动 Rig 而非 Camera（与 FPS 相反）

### 5.2 缩放实现方案

| 方案 | 实现方式 | 适用场景 |
|------|---------|---------|
| Camera Z 偏移 | Camera 沿局部 Z 轴前后移动 | 透视摄像机 |
| Orthographic Size | 改变正交摄像机 size | 经典经营模拟 |
| FOV 变化 | 改变视野角 | 伪正交风格 |

### 5.3 双阶段缩放（高级模式）

来自 Janix 项目的 Issue #209：
1. **即时阶段**：将上一帧渲染结果作为光栅图直接缩放显示（立即可见）
2. **异步阶段**：在新缩放级别重新渲染场景
3. **交换**：新渲染完成时替换缓存

优点：**零延迟反馈** + 高质量最终渲染

### 5.4 平移实现

```csharp
// 使用射线投射到地面平面
Plane groundPlane = new Plane(Vector3.up, Vector3.zero);
Ray ray = camera.ScreenPointToRay(mousePosition);
if (groundPlane.Raycast(ray, out entryPoint)) {
    dragStart = ray.GetPoint(entryPoint);
}
// 拖拽时:
newPosition = rig.position + (dragStart - dragCurrent);
```

**边缘滚屏**（PC）：
```
normX = mouseX / screenWidth
normY = mouseY / screenHeight
if normX > 0.98 → 右移
if normX < 0.02 → 左移
```

## 六、视角选择对宗门游戏的参考建议

基于 XianxiaSect 的现状（Android、2D Canvas 渲染、宗门地图、弟子管理、放置经营），以下为具体的参考建议：

### 6.1 当前状态评估

宗门地图目前使用 **2D Canvas 按格实时绘制**（地面/装饰/建筑三层分离），支持平移和缩放。代码如下已有 `Camera` 类（位置 x,y + zoom level）和单指/双指手势。

### 6.2 行业对标结论

| 决策 | 行业内做法 | 参考来源 |
|------|-----------|---------|
| **投影方式** | 宗门地图已使用正交投影 ✅ | 行业标准做法 |
| **瓦片比** | 需要明确选择 2:1（标准 isometric）还是 4:3（更陡视角） | Clash of Clans, SimCity |
| **旋转支持** | 宗门类游戏通常不需要旋转（增加交互复杂度、需要 4 方向精灵） | Factorio, 开罗游戏 |
| **缩放层级** | 2-3 级（特写→标准→缩略）为黄金数量 | 4E 模型, 移动 SLG |
| **手势** | 单指平移 + 双指缩放为事实标准 ✅ | Supercell, 行业通行 |
| **渲染** | 2D Canvas 按格绘制在放置类游戏中非常常见 | 开罗游戏, RimWorld（原版） |

### 6.3 建议考虑的方向

1. **信息层级设计** — 参考 4E 模型，明确每级缩放展示的信息密度：
   - 拉远时：显示宗门整体布局、资源分布
   - 居中时：显示建筑状态、人物位置
   - 拉近时：显示弟子/建筑详情（无需切换到单独界面）

2. **遮挡处理策略**（如果未来改为斜视角）：
   - 建筑底部半透明化
   - 选中建筑时自动降低周围建筑透明度
   - Zoom-in 时墙壁/屋顶透明（Citadelum 做法）

3. **速度缩放联动** — 缩放越远平移速度越快，缩放越近平移速度越慢

4. **软边界弹性** — 在宗门地图边缘提供弹性阻尼，提升手感

5. **Camera Rig 架构** — 如果尚未采用，建议分离 camera 变换和 rig 变换
