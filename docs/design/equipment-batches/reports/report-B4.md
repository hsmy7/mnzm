## 2. S9/S16 占比校准（⑤ 的推导过程与全阶段对比表）

### 2.1 判据形态

**拍板口径**：装备（含套装 2/4/6 档）贡献 ∈ 弟子总战力 [35%,45%]。落地为**固定 40 种子场景集的中位占比**——战力公式（attack×5 + maxHp×4 + defense×3 + speed×2）不消费暴击/类型词条，同面板个体方差天然大（下表 p10–p90 ≈ ±10pp），中位是口径锚；`EquipmentPowerParityTest` 以断言钉死，任何人动数值表/境界基础属性出带即红。

### 2.2 为什么只调 T6 档（校准推导，实测数据）

k=1 实测（40 种子/阶段，lietian 满套 Lv30）：

| 阶段（入口境界/档） | 基础战力 | 占比 p10 / med / p90 | 主词条战力/B | 副词条战力/B |
|---|---|---|---|---|
| 炼气/T1 | 1,071 | 36.3% / **54.6%** / 65.6% | 0.629 | 0.560 |
| 筑基/T1 | 2,671 | 18.6% / 32.5% / 43.3% | 0.252 | 0.225 |
| 金丹/T2 | 6,937 | 20.9% / 35.2% / 46.3% | 0.289 | 0.249 |
| 元婴/T3 | 18,146 | 22.8% / 36.4% / 47.7% | 0.325 | 0.249 |
| 化神/T4 | 48,033 | 24.6% / 38.2% / 48.8% | 0.373 | 0.247 |
| 炼虚/T5 | 117,414 | 29.0% / 43.5% / 54.4% | 0.464 | 0.310 |
| 合体/T5 | 277,524 | 14.7% / 24.6% / 33.5% | 0.196 | 0.131 |
| 大乘/T6 | 619,092 | 19.0% / **30.8%** / 40.7% | 0.269 | 0.178 |
| 渡劫/T6 | 1,280,880 | 10.2% / 17.7% / 24.9% | 0.130 | 0.086 |
| 仙人/T6 | 2,668,500 | 5.2% / 9.4% / 13.7% | 0.062 | 0.041 |

三条结构性结论（均实测核实）：
1. **均匀 k 在六个入口阶段不可能同时入带**。解 k 使各阶段中位 = 40%：T1@炼气 **0.17**、T2@金丹 1.45、T3@元婴 1.29、T4@化神 1.13、T5@炼虚 **0.77**、T6@大乘 **1.82**——炼虚与大乘对 k 的要求方向相反。T1@炼气更存在 k 不可达下限：**副词条单独占比已达 35.9%**（T1 flat 基数 3/30 相对炼气基础 32/203/23 过小，而副词条杠杆不在「主词条基数 × k」授权面内）。
2. **T6 档偏低的主因**：暴击率/暴击伤害/物法类型词条不进战力公式，T6 档该类权重占比最高（主词条池 3/4 档含暴击 + 副词条 60% 权重为比例类）⇒ flat 主词条的战力杠杆在 T6 被稀释最重。
3. **深化期衰减是结构性的**：渡劫/仙人无更高品阶可穿，T6 基数固定而境界基础属性 ×2.1/×2.1 继续增长，占比必然下行（17.7%→9.4%）——这不是校准可修，属品阶表上限（T6 封顶）的自然结果，将来出 T7+ 时自然回带。

**校准决策**：锚定阶段 = **大乘期 T6 满套**（方案 §3.7 数值示例、S16 经济契约、终局内容三者的共同锚）；仅 T6 档 flat 主词条基数 ×1.8（k_T6=1.8，T1–T5 档 k=1 保持原带内状态）。校准后 T6@大乘 **38.25%** 入带，五个入口阶段（金丹 35.2 / 元婴 36.4 / 化神 38.2 / 炼虚 43.5 / 大乘 38.25）**全部在 [35,45] 带内**并由测试钉死；炼气 T1（54.6%）与深化期（渡劫 23.0 / 仙人 12.6）只登记不设断言（结构性，见 §7 登记 1/2）。

校准后全阶段表（`EquipmentPowerParityTest.全阶段占比对比表输出` 实测打印）：

### 2.3 分维度与件套梯度

- 2/4/6 件套中位占比（大乘 T6）：**26.68% → 31.29% → 37.76%**，严格单调，测试断言。
- 6 件满套 = 2/4/6 三档同时生效（`EquipStatResolver` 口径），占比锚落在满套状态 = 拍板 #6「40% 含套装效果」的满套读法；套装档位效果单列输出（`resolveSetBonus` 断言：lietian 2/6 档物理伤害 0.30、4 档暴击率 0.12、flat 零贡献）。

## 4. ⑥ 期望获取成本量化（I9 触发基线，真概率数学）

口径：掉落链 = 套装 1/2 × 部位 1/6 × 主词条 1/|部位池| × 品阶阶梯（`pickRarity` min=1 顶境：T1 50%/T2 25%/T3 15%/T4 7%/T5 2%/**T6 1%**）；「理想件」= 同套装 + 同部位 + 理想主词条 + T6（无洗练 I3 ⇒ 理想停在主词条层）；锻造链 = 12 配方**天然定向套装+部位**（B3 已立），品阶 = 职业等级上限、T6 成功率 25%、每次锻造（含失败）整耗材料、主词条每炉重 roll。

| 通道 | 量 | 期望次数 |
|---|---|---|
| 掉落 | 理想件（按部位池 2/4/3/5/3/5） | **2,400 / 4,800 / 3,600 / 6,000 / 3,600 / 6,000 件掉落** |
| 掉落 | 六件理想套（精确容斥，不等概率收齐） | **11,389 件掉落** |
| 锻造 | 单件理想 = 4×|主词条池| | **8–20 次锻造**（头 8 / 身 16 / 手 12 / 脚 20 / 武 12 / 腿 20） |
| 锻造 | 六件理想套 | **88 次锻造**（含失败材料整耗） |

**已登记进方案 §九 I9 行**（「期望成本表产出并登记进 I9」判据 ✓）。结论：无保底的随机痛感集中在**掉落链**（万件级）；**锻造链已是定向获取通道**（I9 原定的补救方向「锻造定向指定部位」事实上已由 12 配方承担），真正的缺口是主词条定向/洗练——I9 触发时应优先评估「锻造指定主词条/洗练」而非新建定向链。锻造 88 次理想套的材料整耗（T6 档 4 种材料 × 每次 4–19 件）叠加满级 940 万灵石，构成装备线的第二消耗汇，已可审计。

## 5. ⑦ 速度/灵力塌陷对比与补偿结论

旧体系取证（B3 前表 `fa36109fc:EquipmentDatabase.kt` 原值）：旧 T6 靴「鹤岚靴」速度 **4,575**（+HP 59,100）；旧 T6 饰品「长明坠」灵力 **30,150** / 速度 **4,575**；T3 档「云栖靴/迅捷珠」速度各 155、「灵泉戒/迅捷珠」灵力 645–968。孕养乘区最高另乘 ~2×。

| 阶段 | 基础速度 | 旧装备速度（靴+饰 T6=9,150 / T3=310） | 塌陷幅度 | 基础 maxMp | 旧灵力（T6=30,150 / T3≈968） | 塌陷幅度 |
|---|---|---|---|---|---|---|
| 元婴（T3 期） | 255 | 310 | **−121.6%** | 1,326 | ≈968 | **−73.0%** |
| 大乘（T6 期） | 8,700 | 9,150 | **−105.2%** | 45,240 | 30,150 | **−66.7%** |
| 仙人（T6 期） | 37,500 | 9,150 | −24.4% | 195,000 | 30,150 | −15.5% |

消费面影响：速度入战力公式（×2 权重，装备速度旧贡献 ≈ 大乘总战力 2–3%）与战斗**闪避率**（`battle_calculator.h:491 calculateDodgeChance(attacker.speed, defender.speed,…)`）；灵力池影响技能释放（面板+恢复结算）。**战力占比面不受影响**（速度不在装备加成通道，40% 校准干净）。

**结论：不启用备选补偿（维持 §13-13 拍板默认「先不补偿」）。** 理由：① 塌陷是 R 需求本体（S14「装备不再提供速度灵力」已拍板），非缺陷；② 备选 B1（脚部池加回速度）/B2（提升基础速度成长）切换成本已写明且保持可用（B1 = 改 §3.4.2 表 + 池数据行 + C++ 对偶表；B2 = `GameConfig.Realm` 成长常量），上线后若战斗节奏（闪避/灵力续航）反馈负面，作为 I9 相邻杠杆启用；③ 本批刚完成占比校准，任何速度补偿都会再动战力分母，应与首次真机平衡反馈同批做而不是现在预置。监控建议（随 I9 族登记）：上线后观测战斗回合数与闪避率分布偏移。

## 6. 决策登记（本批新增，勿翻案）

1. **热点缓存 = 恒等键整解析缓存**（`EquipStatResolver.resolveCache`，4096 清空重建护栏）。对方案 §13-6 字面「按实例内容做值语义缓存」的**实测修正**：值语义键（新模型深层嵌套 data class）每调用 6 次全树深哈希，实测 1,286 ns/调用、对改造前基线 6.3 倍劣化（缓存本身只省 12%——瓶颈在哈希不在重算）；改恒等键后 124–161 ns/调用。版本安全性：`EquipmentInstance` 全字段 val（内容不可变）、唯一 `var slotId` 不参与加成且变更走 `copy`（新恒等=新键）⇒ 内容变必然新键，零失效逻辑。代价：反序列化出的等值新实例（UI 读路径）不命中——等同改造前无缓存状态，无回归。
2. **月产出锚 = 940 万灵石/月**（T6 可穿阶段标准月画像，拍板口径反推定锚、非测量值）——§3 已详述，B5 落经济基线表。
3. **占比判据 = 固定 40 种子中位 ∈ [35,45]**，断言落五个品阶入口阶段（金丹/元婴/化神/炼虚/大乘）；炼气 T1 与深化期结构性出带，只登记不设断言（§2.2）。
4. **基准门臂结构 = 分配画像对称**：改造前基线复刻臂与现行臂每调用同样构建槽位列表 + 一次键包装 + 一次映射探测——首版非对称臂在套件负载下比值虚胖到 1.31（GC 压力打在分配多的一侧），对称化后空载 0.603 / 套件负载两轮 0.317、0.282，门 ≤1.10 稳定。
5. **AI 装备零加成维持登记语义**：`Gear.kt`/`ai_sect_ops.h` 双端同构占位空词条实例（I5），KDoc 中「战斗装配按品阶固定加成（C++ 侧，B4 对齐）」一句为 B3 遗留的**前瞻表述而非本批义务**——实测双端均按占位 0 加成结算、语义已一致；是否给 AI 按品阶装备加成属产品数值决策，登记 §7。
