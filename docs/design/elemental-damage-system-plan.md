| 元素 | 覆盖角色 | 覆盖率 | 说明 |
|---|---|---|---|

**关键推论（与早期估算的差异，必须按此校准）**：

1. **玩家侧元素词条的有效度 = 该元素覆盖率**（角色设计固定 ⇒ 无随机）：金/木/土 33%、水 50%、火 **17%**、物理 **100%**。
2. **双灵根角色可吃两系加成**（名册 6 个里 4 个是双灵根，如角色 6 = 火+土 ⇒ 同时适配火套与土套）⇒ 这是**策略点**，不是缺陷。
3. 早期文档写的"81% 覆盖率"基于已废弃的随机权重，**已作废**；P9 的数值补偿改为按上表覆盖率的**加权期望**推导（§3.5）。
4. AI 侧仍按权重随机 ⇒ AI 弟子的元素分布与玩家侧**不同口径**（AI 覆盖率按权重 ≈ 某元素 81%）。两套口径**互不影响**：玩家配装看名册，AI 只是敌人数值。

## 三、目标架构

### 3.1 伤害类型：`DamageType` 2 → 6 值

```kotlin
@Keep
@Serializable
enum class DamageType {
    // 编号 1 = 原 MAGIC 退役段（保留 reserved 语义，禁复用）
    @ProtoNumber(0) PHYSICAL,   // 物理：普攻恒为此；部分功法招式
    @ProtoNumber(2) METAL,      // 金
    @ProtoNumber(3) WOOD,       // 木
    @ProtoNumber(4) WATER,      // 水
    @ProtoNumber(5) FIRE,       // 火
    @ProtoNumber(6) EARTH;      // 土

    /** 五行元素（用于伤害加成与抗性的索引）：6 值中的 5 条元素通道 */
    val element: String? get() = when (this) {
        METAL -> "metal"; WOOD -> "wood"; WATER -> "water"
        FIRE -> "fire"; EARTH -> "earth"; PHYSICAL -> null
    }
}
```

- `MAGIC` 的 Proto 编号 `1` **退役**（`reserved`，不复用），避免旧存档把"法术"解成某个元素。
- 五行伤害类型与 `GameConfig.SpiritRoot.TYPES` 的 key **一一对应**（`metal/wood/water/fire/earth`），不新建第二份元素枚举。

### 3.2 类型判定：普攻固定物理 + 技能由功法自带

```
isPhysical → 伤害类型判定（6 值）
  普攻：恒为 PHYSICAL（所有角色，与灵根无关）
  技能：skill.damageType（功法写死，6 值之一）
攻击力/防御力：单列 attack/defense（装备重构 §15 已定），与伤害类型无关
```

- **普攻不参与灵根随机**（P3 + 用户明确"目前所有角色的普攻均设计为物理伤害"）。
- 技能不随持有者灵根改变属性（E3）⇒ 同一本功法对不同弟子的**伤害属性一致**，但**加成是否生效取决于弟子灵根**（§3.3）。
- `BattleCalculator.kt:362-363` 的"普攻按物攻≥法攻判定"**删除**（单列后本就失效）。

### 3.3 灵根 gate：五行加成的生效规则

```
弟子灵根集合 = Disciple.spiritRootType 按 "," 拆分的元素集合
五行伤害加成生效系数 gate(弟子, 元素) = if (元素 ∈ 灵根集合) 1.0 else 0.0

生效的五行伤害加成 = Σ over 该次攻击的元素(仅 1 个) : 该元素伤害加成 × gate(弟子, 元素)
```

| 弟子灵根 | 对"火伤害加成 +15%"的生效情况 |
|---|---|
| 单火灵根 / 双(含火) / 三(含火) / 四(含火) / 五灵根 | **全额 +15%** |
| 无火灵根的弟子 | **0（完全不生效）** |

- **物理伤害加成不受 gate 限制**（普攻人人物理 ⇒ 物理词条 100% 有效，E11）。
- gate 是**纯乘性开关（1 或 0）**，不做按灵根数量的线性折算（决策见 §14 Q4）。
- 设计意图：灵根从"背景设定"变成**配装约束**——玩家要给弟子配与其灵根匹配的套装/词条。

**档位值（P9 补偿：类型词条整体 ×1.5）**：

| 词条 | 品阶 1 | 品阶 2 | 品阶 3 | 品阶 4 | 品阶 5 | 品阶 6 |
|---|---|---|---|---|---|---|
| 攻击力 | 1 | 3 | 8 | 21 | 64 | 195 |

| **6 条类型伤害加成**（物理 + 五行，同档） | **0.006** | **0.009** | **0.012** | **0.018** | **0.024** | **0.030** |

- **补偿依据（已按名册实测修正）**：玩家侧角色灵根为设计值，**按灵根配装时元素词条 100% 有效、错配时 0**；名册加权平均覆盖率 = (2+2+3+1+2)/(6×5) = **33%**（"随机穿装"口径）。物理词条**恒 100%** 有效。⇒ ×1.5 的价值仅在"玩家不按灵根配装"时成立；会配装的玩家会白得 50% 增益。**最终由数值校准批按 E12 判定**（三个候选：① 与通用同档不补偿 + UI 引导；② ×1.5；③ ×1.25 折中）。
- 物理伤害加成与五行伤害加成**同档**（不给物理额外系数），但因不受 gate，其期望效率本就更高——这是刻意的"稳妥选择"（物理人人都能吃到）。

### 3.6 类型抗性：防守方 6 桶

```
DamageZones.damageReduction（单值）→ physicalReduction / metalReduction / woodReduction
                                    / waterReduction / fireReduction / earthReduction
```
- 各桶默认 `0.0` ⇒ 未配置时**与装备重构后的公式逐位一致**（不改变既有数值）。
- 妖兽/护甲可配置"高物抗低火抗"等；**不做相克**（P8）。
- 与攻击方类型加成的对应关系严格按 `DamageType` 索引，**一一对应、不交叉**（E5/E6）。

### 3.7 数值管线（完整口径）

```
① 面板（单列，装备重构已定）
   attack  = (base + Σ装备flat) × (1 + Σ装备ATTACK_PCT) + Σ功法flat + Σ丹药flat
   defense = 同构

② 战斗期类型通道（本任务新增）
   元素      = 普攻 ? PHYSICAL : skill.damageType            // 6 值
   类型加成   = 该元素对应的伤害加成 × gate(弟子, 元素)          // 物理 gate 恒 1.0
   类型减伤   = 守方该元素对应的减伤桶

③ 伤害
   = attack × 技能倍率 × (1 − defense/(defense+500)) × 暴击区
   × (1 + 通用增伤 + 类型加成) × (1 − 通用减伤 − 类型减伤)
   × 境界压制 × 波动 × 段数                      ≥ 1
```

**算例**（`attack=1000`、守方 `defense=500` ⇒ 减伤 0.5；普攻、倍率 1.0、不暴击、无波动/境界因子）：

| 弟子 | 普攻元素 | 装备 | 灵根 | 守方抗性 | 结果 |
|---|---|---|---|---|---|
| 甲 | 物理 | 物理套 6 件（物理伤害 +30%） | 任意 | 物理减伤 10% | 1000 × 0.5 × 1.30 × 0.90 = **585** |
| 乙 | 物理 | 火套 6 件（火伤害 +30%） | 含火 | 物理减伤 10% | 1000 × 0.5 × 1.00 × 0.90 = **450**（火加成对普攻不生效） |
| 丙 | 火（火系技能） | 火套 6 件 | **含火** | 火减伤 0% | 1000 × 0.5 × 1.30 × 1.00 = **650** |
| 丁 | 火（同一技能） | 火套 6 件 | **不含火** | 火减伤 0% | 1000 × 0.5 × **1.00** × 1.00 = **500**（gate=0） |

⇒ 丙 vs 丁 的 30% 差距**完全来自灵根**，这就是 P4 的落点。

## 十三、盲区自查

**13-E1 需求理解**：五灵根占 40%，若 gate 为开关制，则五灵根弟子能吃到全部 5 系加成（最"通用"），单灵根只吃 1 系 —— 与"单灵根稀有=强"的既有设定**方向相反**。本任务**不修正**该矛盾（灵根数仍只影响修炼速度），但需在 UI 说明"杂灵根适配面更广"。**建议**：若将来要修正，走 I-E4（线性折算）。
**13-E2 边界**：弟子灵根为空串 / 含未知元素 / 含重复元素 → gate 视为"不含"，并记 `Log.w`（`EquipmentValueSanitizeRule` 补规范化）。
**13-E3 系统耦合**：技能元素来自功法，故**功法图鉴/学习界面**需展示元素标签（否则玩家无法配装）；已列入 WP-E4。
**13-E4 假设有效性**：假设"普攻恒物理"对所有未来角色成立 —— 若未来加入"法术普攻"角色，需扩展 `innateDamageType`（装备重构已预留该字段，可直接复用为"普攻元素"）。
**13-E5 非功能**：6 路加成的结算比 2 路多 4 次查表，属常数级；但 `EquipBonus` 解析在每旬热点上被调用 ⇒ 沿用装备重构的基准测试（不劣化 >10%）。
**13-E6 生命周期**：36 张精灵图的缺图兜底必须与装备重构的占位方案一致（否则两套占位风格并存）。
**13-E7 流程**：本任务与装备重构**同属装备域**，若两线并行必冲突（§0）；`docs/realtime-watch/DISPATCH-LEDGER.md` §8 需在其后追加"E 批"。
**13-E8 内容依赖（本轮新发现）**：名册仅 6 角色，**火元素只有角色 6 一个**（17%）⇒ 火套/火词条目前只服务 1 个角色。**要求策划侧同步**：若要 5 元素套都成立，每个元素应至少 1 个专属角色 + 该系功法（当前木/火/土的角色数与功法覆盖需复核）。否则建议**先上物理 + 水/金/木/土，火套延后**，或按实际名册决定套装数量。
