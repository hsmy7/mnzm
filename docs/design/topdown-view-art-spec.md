# 宗门地图统一俯视视角——素材替换规范（美术操作手册）

> 2026-09 视角统一工程配套文档。渲染侧已全部改为**俯视锚点语义**（建筑/门楼贴地 1:1、
> 树冠居中），本文档告诉美术：每张素材的**尺寸、纵横比、内容要求与替换流程**。
> 新素材按本规范放入后，**无需改任何代码**，跑一次图集构建即可生效。

---

## 1. 统一视角基准（所有素材必须遵守）

| 基准 | 规定 |
|---|---|
| 摄像机 | 接近正上方的俯视投影（引擎已实现）：正交、无旋转、无近大远小；整屏 Y 轴按 `TOPDOWN_Y_SCALE = 0.75` 压缩模拟俯角（约 48.6° 仰角观感，与 Clash of Clans 的 4:3 地面瓦片同观感——地面格在屏上呈 4:3 矩形；双端共享常量，改值只动 `build-atlas.mjs` LAYOUT 一处）。整张地图如同同一台固定俯视摄像机拍摄 |
| 素材视角 | 立体素材（建筑/草石树）按"立绘"作画即可——引擎按素材纵横比换算显示尺寸（屏上不变形），**不要**在素材里预补偿俯角；俯视贴地素材（灵田/作物/地面/道路）按真实俯视比例绘制（正方形格子画正方形顶面） |
| 立体感 | 仅保留轻微 2.5D：南侧可露少量墙体/厚度，**禁止**正面立绘、侧视、传统 45° 等距（菱形地砖/斜屋顶） |
| 透视 | 禁止透视缩放——远处不缩小，屋脊/道路保持水平垂直（与地面网格轴对齐） |
| 光照 | 光源西北（左上）→ 阴影朝东南（右下）；建筑阴影由引擎自动绘制（0.25 格右下偏移、alpha 0.2），**建筑素材内不要再自带大面积投影** |
| 朝向 | 所有建筑南墙（正门）统一朝地图 +Y 方向（下方）；屋顶屋脊一律东西走向（水平） |
| 风格 | 2D 国风修仙：清新简洁、低饱和度、中高亮度、轮廓清晰（1–2px 深色描边）、细节适中、非写实 |

## 2. 渲染锚点契约（工程已固化，美术只需对齐尺寸）

**总口径（2026-09 起）：立体素材按"屏上不变形"取值，俯视贴地素材按世界网格取值。**

| 类别 | 显示尺寸公式 | 说明 |
|---|---|---|
| 立体建筑（18 栋立绘） | 精灵宽 `W = 占地宽`；精灵高 `H = round(W × 素材高 ÷ (0.75 × 素材宽))` | `0.75` = `TOPDOWN_Y_SCALE`（地图纵向压缩）；除以它后素材在屏上恢复原比例。**允许 `精灵高 > 占地深`**（塔/楼向上多占格），`精灵 ≠ 占地` 是常态 |
| 俯视贴地（灵田；作物/瓦片/道路/岛边缘/门楼） | 世界纵横比 = 素材纵横比（与地格平铺对齐） | 灵田 1×1、门楼 6×2 —— 精灵 == 占地 |
| 装饰（草/石/树） | 与立体建筑同式（小数格精度：草 1×1.157、石 1×0.909、树 2×3.291） | 锚点 = **格底边居中**（对象"站在"自己格子上）；树冠向上伸出、草石略高于格 |

- **建筑锚点**：精灵底边对齐占地底边、水平居中（`offsetX = (fpW − sw)/2`、`offsetY = (fpH − sh)`）；
  **占地 = 建筑底座**（宽 = 精灵宽：左右不压盖；深 = 底座进深：塔/亭 2 格、池 3 格、院落/山丘/殿保持现状）。
- **画家序**：立体装饰（树）与建筑按**地面接触点（底边 Y）**统一归并，同键时建筑在后
  （建筑压住同接触点的装饰）；草/石跟随地面逐格绘制。
- **回归防线**：`build-atlas.mjs` 构建期校验 + `SpriteSizingFidelityTest` 测试期校验
  「屏上纵横比 == 素材纵横比（容差 7%）× 精灵宽 == 占地宽 × 精灵高 ≥ 占地深」；
  `BuildingSpriteFootprintGuardTest` / `BuildingSpriteFootprintJsonGuardTest` 锁配置数值。
  改尺寸只改 `LAYOUT.tiles[].sprite`（装饰）与 `config/buildings.json`（建筑，含 `Defaults.kt` 兜底镜像）。
- **宗门门楼**：占地 6×2、精灵 6×2，贴地对齐（原 6×4 上悬已废除）。
- **树**：精灵画在以树格中心为轴、底边贴格底边的 2×3.291 格内——树冠为主体向上，底部露树干/根盘。
- **草 / 石**：底边贴格底边、水平居中，草略高于 1 格、石略矮于 1 格（按素材比例）。
- **岛边缘 / 云 / 道路 / 地面**：维持现状（已是俯视语义），无需替换。

## 4. 替换清单与规格表

**通用画布规则**（重要）：
- 图集构建用 `fit: fill` 把源图**强制拉伸到槽位尺寸**，所以源图请直接**按槽位尺寸的
  2 倍**作画（透明底画布，纵横比与槽位一致；门楼槽位为 768×256 非方形）。
- 建筑槽位为正方形（512²/1024²/128²）而显示内容非 1:1 时，内容按"显示纵横比"
  在画布内居中放置（letterbox），其余留透明。
- 内容与槽位边缘保留 ≥2px 透明边距（mip 防渗色）；槽位间距 8px 由布局自动保证。
- 交付格式：**无损 WebP**（与现役一致），替换同名文件。

## 5. 替换流程

### 路径 A：建筑 / 门楼（不在 source-mapping 管控内）
1. 用同名**无损 WebP** 替换两个模块的
   `android/app/src/main/res/drawable-nodpi/<name>.webp` 与
   `android/feature/game/src/main/res/drawable-nodpi/<name>.webp`（两份必须一致）。
2. 重建图集：
   ```bash
   cd android && node scripts/build-atlas.mjs
   ```
   （会重新生成 `app/src/main/assets/atlas/atlas_astc.ktx` + `atlas-manifest.json`；
   Gradle 构建时 Kotlin/C++ 布局代码自动同步，无需手工改。）
3. 安装运行验收：建筑屋顶与网格 1:1 对齐、树冠居中于格、无立牌悬出。

### 路径 B：草 / 石 / 树 / 草皮 / 门楼 / 天枢殿 / 灵草作物（source-mapping.json 管控）
这些由 `scripts/source-mapping.json` 登记源图与烘焙参数（`MAP` 分类 = 地图装饰与地面；
`BUILDING`/`ITEM` 分类 = 天枢殿/灵草作物）：
1. 替换 `D:\模拟宗门美术素材` 下对应源图（草：`装饰物/花草1..4.png`；石：`装饰物/石头1..3.png`；
   树：`装饰物/树木1..2.png`；草皮：`装饰物/草皮.png`；门楼：`建筑/宗门门楼.png`；
   天枢殿：`建筑/天枢殿.png`；灵草：`草药生长期/龙血草成长期.png`、`风铃草成长期.png`、`九转灵草成长期.png`）。
2. 重新导入并重建：
   ```bash
   cd android
   node scripts/scaffold-source-mapping.mjs   # 源图新增/改名时先跑（登记映射）
   node scripts/import-art-assets.mjs         # 烘焙无损 WebP 到双模块（内容 hash 增量）
   node scripts/build-atlas.mjs               # 重建图集 KTX + 布局 codegen
   ```
3. 源图纵横比变化时无需改参数（图集按槽位 `fit: fill` 缩放），但**构图必须按槽位纵横比作画**，
   否则会被拉伸；草皮带 `bake.seamless`（无缝平铺，输出 64×64），改草皮无需额外操作。

> 注意：路径 A 的文件若直接重跑 import 不会生效（不在 mapping 内）；路径 B 的文件
> 不要直接改 drawable webp（会被下次 import 按源图覆盖）。

## 6. 验收清单（替换后自查）

- [ ] 建筑精灵在屏上的长宽比与素材一致（无压扁/拉宽）；塔/楼类明显高于其占地（巡视楼 4×10、问道塔/青云塔 4×8）
- [ ] 建筑底座（南侧台基/台阶）落在占地矩形内，放置预览（绿框）与底座对齐
- [ ] 相邻建筑（占地相接）精灵不左右互相压盖（精灵宽 == 占地宽）
- [ ] 树：树干立在格底边、树冠向上伸出；树在建筑前方时遮住建筑、在后方时被建筑遮住（层序正确）
- [ ] 草/石底边贴在格底边、略高于（或略矮于）1 格，与相邻格不产生错缝
- [ ] 缩小到全景（缩放下限）观察：整岛仍是"正上方俯瞰一座浮空岛"的观感；放大到上限观察建筑/装饰边缘不糊
- [ ] 换图后跑过 `node scripts/build-atlas.mjs`（构建期保真校验通过：`显示尺寸保真校验通过：19 栋建筑 + 9 个装饰`）
