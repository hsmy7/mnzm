## 3. 设计原则

1. **单机抽卡，学体验不学付费**：公示、记录、十抽保底服务"每次寻访有进度感"。
2. **角色全预设，物品走品阶**：品阶（六阶制）只用于物品掉落；角色稀有度由灵根配置承载，单灵根=稀有+强力（修炼 2 倍速），稀有与强大自动重合。
3. **移除即善后**：每拔一个机制，全部读写点与下游逐项给出去向（§5–6，含招募退役 §6.8、重伤替代战死 §6.9）。
4. **参数全部配置化**：池概率/品阶概率/碎片门槛/保底/转化比例走 `game-data.json` 新表 + `data_inject` 注入 + 生成器脚本；池配置表按多池结构设计（轮换池零成本预留）。
5. **与进行中的施工隔离**：SR 存档云重构（SR2–SR7）正改 `GameData`/`Disciple.kt`/`StorageEngine`，本重构单独批次、单独分支、对表串行。
6. **C++ 权威、单点入口**（v1.4 补）：抽卡 roll/保底/碎片/升星判定一律 C++ 实现（Kotlin 只展示）；物品发放走 `InventorySystem` 统一入口；角色实例化走 `templateId` 单点；新增状态写者不新增反向同步通道。

## 4. 寻访（抽卡）系统设计

### 4.1 常驻池结构与概率（拍板数值）

单抽 5,000 灵石；背景/按钮 = `普通招募背景图` + `普通招募一次/十次ui`。

**类别概率**：

| 类别 | 概率 | 明细 | 结果 |
|---|---|---|---|
| 单灵根角色 | 11% | 周明 5.5% · 苏晴 5.5% | 该角色碎片 ×1 |
| 双灵根角色 | 10% | 林雪棠 2.5% · 许荷 2.5% · 谢澈 2.5% · 赵言 2.5% | 该角色碎片 ×1 |
| 妖兽材料 | 26% | 品阶 roll 后品阶内均匀抽取 | 物品入宗门仓库 |
| 草药 | 26% | 同上 | 物品入宗门仓库 |
| 种子 | 27% | 同上 | 物品入宗门仓库 |

**物品品阶概率**（三类各自独立 roll，一阶=凡品 … 六阶=宝品）：

| 品阶 | 六阶 | 五阶 | 四阶 | 三阶 | 二阶 | 一阶 |
|---|---|---|---|---|---|---|
| 概率 | 1% | 3% | 10% | 34% | 32% | 20% |

**保底（拍板）**：每 10 抽必得**任意一角色碎片 ×5**。
- 归属解释（假设声明）：默认**随机归属六名角色之一**；若改为"玩家自选归属"，定向解锁速度约提升 3 倍，列为 M0 校准杠杆，待拍板。
- 原 90 抽硬保底/软保底设计**作废**（混池+碎片制下无承接对象）；保底计数器（0–9 循环）入档。
- **十连×保底结算（v1.4 补，实现契约）**：计数器全局 0–9，**每次抽卡（无论单抽/十连内第 n 抽）独立先 roll 类别再 `count++`；当 count 达到 10 时先重置为 0 并额外发保底碎片 ×5**。十连 = 顺序执行 10 次单抽语义，跨十连边界计数连续；结果页对每抽标注「保底」来源，历史记录同步 x/10。计数器随存档（SL 回档回退，已拍板接受）。

**物品入库（v1.4 补，工程铁律）**：三类掉落必须走 `InventorySystem.addXxx` 统一入口并 `withTrackingSource("仙缘寻访")`（来源名登记 `OverflowMailSender.SOURCE_DISPLAY_NAMES`）；**发放类**语义（不包 `withOverflowMailSuppressed`）——仓库满时溢出自动转邮件，抽卡流程永不因满仓失败。

**灵石不足（v1.4 补）**：余额 < 单抽价 → 单抽按钮禁用 + 文案「灵石不足」；余额 < 十连价 → 十连按钮同策略；**不做差额部分抽取**。

### 4.2 角色碎片与星级制（拍板）

- 抽中角色 = 获得**该角色碎片 ×1**（无论是否已解锁，一律得碎片——Q18 修订 Q8/Q17 的"转灵石"口径，**碎片转灵石路径取消**）。
- 星级阈值（累计碎片，达标自动升星）：

| 星级 | 1 星（解锁） | 2 星 | 3 星 | 4 星 | 5 星（满） |
|---|---|---|---|---|---|
| 累计碎片 | 100 | 200 | 300 | 400 | 500 |

- 解锁（1 星）即生成对应弟子入宗（模板实例化）；**限持 1 份**不变，重复抽取喂养星级。
- **星级效果（拍板：全属性乘区）**：每升 1 星 → 战斗属性 +8%、修炼速度 +5%（strawman，M0 校准终值），全角色统一乘区，进入 `finalStats` 聚合链；5 星满加成 = 战斗属性 +40% / 修炼速度 +25%。每角色专属星魂效果列为 M3 备选，本次不做。
- 5 星满后碎片继续累计（仅作收集记录，无效果——单机接受）。
- 图鉴 UI：6 角色立绘（未解锁置灰）+ 星级（★×n）+ 下一星碎片进度（x/100）；弟子卡与详情页展示星级。
- 碎片库存、星级、保底计数器：新 `@ProtoNumber` 字段入档。

### 4.3 角色定义层（6 具名预设模板）

| 角色 | 灵根 | 定位 |
|---|---|---|
| 周明 | **单灵根**（元素待定，走配置表） | 修炼 2 倍速，强度担当 |

| 林雪棠 / 许荷 / 谢澈 / 赵言 | 双灵根（元素对待定） | 标准速 |

**风格锚点**：火影忍者手游招募结果——**上下横线 + 中间半透明面板**，奖励网格居中；不做长动画（§10），结果页即主舞台。

**布局（固定规格）**：

| 元素 | 规格 |
|---|---|
| 网格 | **两行 × 五列**，十连满格 10 |
| **单抽布局** | **仅 1 个方框，且该框在网格区域/面板内居中显示**（不贴左上角；十连仍按 2×5 铺满） |

| 物品框内容 | 物品图标（居中）+ **数量角标** |
| **数量角标** | **框内右下角**；文本如 `×3` / `×1`；**字体白色**；可加细描边/半透明底保证在彩色背景上可读；**角色碎片同样右下角白字**（×1/×5 等） |
| **边框流光** | 框边 **持续旋转的流光/描边扫光特效**（无限循环、不打断）；**颜色 = 品阶色（物品）或灵根色（角色碎片）** |

| **颜色总表（Q31，覆盖仓内旧色）** | 见下方两表；**与现有 `GameConfig.Rarity` / 徽章旧口径不一致时，一律以本表为准** |
| 保底碎片 | 流光/背景可用更亮一档或附加「保底」角标（与 §4.1 高亮一致） |
| 顶部标题 | 文本 **「恭喜获得」**，金色；十连与单抽共用 |
| 底部按钮 | **左：招募一次 · 右：招募十次**（素材 `普通招募一次/十次ui`）；扣费与灵石不足禁用态同 §4.1；点击即在**当前结果页上叠下一轮结果**（不先关页再开寻访主页） |
| 关闭手势 | **点击屏幕任意处关闭**，但 **排除**：① 各奖励框（点击可查看详情/不关窗）② 底部双按钮（走再次招募） |
| 升星 | 若本轮触发跨星：结果页之上（或关闭前）弹 **全屏升星提示**（星级跳变 + 加成数值），确认后回结果页/关闭——时序：roll 完 → 升星层（若有）→ 结果页展示 |

## 7. 灵石经济与获取节奏（含 PM 测算，M0 必须复核）

**灵石经济与获取节奏（含 PM 测算，M0 必须复核）**

**开局注入（v1.4）**：新档初始灵石 **50,000** = 恰好 10 抽（含 1 次十连保底必触发）。这是**一次性开局 sink 前注入**，不进入月度收入曲线；M0 白皮书须把「首抽/前十连完成于开局当日」写为基线，并从第 2 月起用纯自然收入重算首角色节奏。

**获取节奏测算**（按拍板数值的期望值）：
- 每抽期望碎片 = 角色 21% × 1 + 十抽保底 0.5 = **0.71 碎片/抽**；
- 碎片近似均匀落六角色 → 单角色 100 碎片（1 星解锁）期望 **≈ 850 抽（425 万灵石）**；六角色全解锁 ≈ 850–1000 抽（考虑方差首解锁可能提前至数百抽）；
- **周明开局已持有（100 碎片等效）** ⇒ 从碎片池中剔除周明解锁需求后，**其余 5 角色全解锁期望 ≈ 700–850 抽**；六角色全 5 星仍为 3,000 碎片总量 − 已送 100 = **2,900 碎片 ≈ 4,080 抽 ≈ 2,040 万灵石**；
- 开局 10 抽期望角色碎片 7.1 枚（随机归属），**开局十连大概率不能当场解锁第二角色**——M0 可用「开局送双灵根 99 碎片」类杠杆校准「第二角色时刻」，默认不送；
- 前期月入数千灵石（开局 5 万耗尽后）→ **第二个角色以现实周/月计**。

1. **角色定义层 = 模板实例化**：6 个具名模板走配置表（`gachaPools` + `characterTemplates`：立绘/灵根/特质组合/初始功法）；`DiscipleCreationSeed` 扩展 `templateId` 路径；收敛构造路径到单点（主工厂/Kotlin 臂/兑换码改道碎片，见 §6.10）。
2. **字段删除三端同步链**（审计 §11⑨）：`models.h` → `DiscipleColumn` → `disciple_store` → `column_dirty` → `json_codec` → Kotlin `Disciple.kt` → Room migration → bijection 守卫。本轮删除字段：寿命/年龄/忠诚/神魂/**亲缘 7 字段/资质/悟性**/**招募族**（`lastRecruitYear`、`autoRecruitSpiritRootFilter`、`autoRecruitIdle`、`recruitList` 容器等）。
3. **协议纪律**：`@ProtoNumber` 只增不复用；旧档靠 proto 默认值 + `GC_FROM` 宽松导入兼容，不动 SR migrator 链；亲缘字符串残留值读档迁移清空；**`recruitList` 读档整表清空**。
4. **新档字段**：碎片库存 / 星级 / 保底计数器 / 寻访历史 → 新 `@ProtoNumber` + Room 扩展。**结构以 §15.3 为准：`map<templateId,…>` / `map<poolId,pity>`（或平行数组），禁止 `6×int` 定长与全局单保底计数。** 星级不落在弟子行上（弟子实例由星级派生加成），星级真相在图鉴/池状态侧。**周明开局解锁位与碎片账本一致**（§4.5）。新字段全部走 `slot_id` 隔离 + `resetForSlot`，过 `ProtobufConverters`/云体积 bench。
5. **RNG 纪律**：抽卡走 SYSTEM 分区，落档后展示；物品掉落"先品阶后品阶内均匀"两级 roll；SL 回档重抽接受。**生育/配对/招募刷新删除平移结算 RNG 序列 → 对拍基线重录**（§13）。
6. **战力口径**：角色强度验收以 `finalStats`/实战为准，不用宗门战力（审计 §11.2/§16.9）。**星级乘区进入 `finalStats` 聚合链，C++/Kotlin 双端实现必须同步加入并纳入既有对拍测试**。
7. **施工隔离**：独立分支独立批次，与 SR、地图 S 系对表串行。
8. **配置化通道**：`game-data.json` 新增 `gachaPools`（类别概率/品阶概率/碎片门槛/保底/转化比例）+ `characterTemplates`（6 角色预设）；物品掉落复用现有 `beastMaterials`(192)/`herbs`(54)/`seeds`(54) 表按 rarity 过滤（三表六品阶分布均匀，已实测可支撑）；禁止双端硬编码。**初始灵石 50000、重结晶 HP=1、旬结回血参数、Q31 品阶/灵根色表**一并可配置或单源常量（禁止结果页与徽章各抄一份）。
9. **抽卡产物入库铁律（v1.4）**：统一 `InventorySystem.addXxx` + `withTrackingSource("仙缘寻访")` + `SOURCE_DISPLAY_NAMES` 登记 + **发放类溢出转邮件**（§4.1）；守卫测试 `InventoryAddPathGuardTest` 必须覆盖寻访路径。
10. **C++ 权威 + 零新增反向通道（v1.4）**：抽卡/保底/碎片/升星/开局注入/重伤回血全部下沉 C++；UI 只读展示。与 reverse-channel-elimination 主轴一致，不新建 Kotlin→C++ 增量写回。

12. **新对话框工程 checklist（v1.4）**：寻访/公示/历史/图鉴 → 注册 `DialogType` → 渲染 `when` 分支 → `DialogSystemBarGuard` → 若含输入则四件套（`rules/dialog-soft-input-guard.md`）；聊天类不用 `UnifiedGameDialog`（非聊天）。

### 15.3 数据模型扩展性（修正 §8.4 旧写法）

|---|---|---|

## 16. 现状与「角色卡池 + 少量长期养成角色」方向的差异（只列事实，不给改造方案）

1. **无定义层**：卡池的前提是"一组预定义角色"。当前 `createDisciple` 的身份字段（名字/立绘/天赋/属性）无入参可覆盖，且 `game-data.json` 无 disciples 表（A）。
2. **id 语义与该方向相反**：已拥有弟子 id = `max+1` 自增数字，且招募瞬间**无条件覆盖**候选 id（`recruit_settlement.h:390 d.id = idStr`，A）；候选 id = UUID；AI 弟子 = `gc-ai-d-N`。该方向需要"配置 id 稳定可寻址且与实例 id 分离"，当前恰好是"实例 id 吞掉一切"。
3. **群体模拟 vs 少量角色**：字段设计面向"成百上千个会老、会死、会叛逃、会生育、会偷盗、会领俸禄的模拟体"（寿命 / 丧亲 / 忠诚 / 叛逃 / 俸禄 / 血炼 / 储物袋 / 师徒 / 亲缘），无"玩家主力角色"与"NPC 消耗品"的类型区分；`discipleType` 只有手动 outer/inner 标签（§14.1）。

5. **稀有度方向一致但机制不是抽取式**：灵根越少越强（个数是修炼速度**除数**，`disciple_stats.h:763-766`，同时是悟性/资质阶梯正向因子，`disciple_factory.h:436-440`），而 1 根概率仅 1%、5 根 40%（`child_birth.h:51-55`）。这是"属性分布的自然尾部"，不是卡池权重。

7. **资源绑定受池大小上限约束**：男 20 / 女 17 是双端字面量区间，第 21 张男头像需改两端代码（A）。
8. **给角色定基础属性的直觉做法当前无效**：写进 `baseHp` 等 7 字段不进任何公式（§11.1，A）。
9. **战力口径与实战口径不一致**：战力用 `baseStats`（不含装备/功法/丹药），战斗用 `finalStats`；若以战力作为卡池验收指标，会出现"战力不涨但实战变强"（或反之）的系统性错位。
