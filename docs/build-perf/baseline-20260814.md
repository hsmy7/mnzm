## 3. 基线期间发现并修复的问题（阶段 0 副产品）

### 3.1 OverflowMailSenderTest flaky（预存问题，已根治）

- **症状**：`drain mail id is deterministic across replays` 偶发失败 `Wanted 2 times: But was 1 time`（基线运行 1 次失败，耗时 1.2s）
- **根因链**（第一性原理）：
  1. `scheduleDrain()` 单飞去重：`drainScheduled` 标志，同时最多一个 drain 周期在途
  2. 测试两次调用若落在同一周期窗口内 → 第二次被合并丢弃 → 仅 1 次 insert
  3. 旧测试用 `Thread.sleep(600)` 分隔两次调用 → 机器慢时（drain 周期 >600ms）第二次调用仍落在窗口内 → 偶发失败
  4. 改造 sleep→timeout 时删掉间隔 → 两次调用必然合并 → 确定性失败（改造引入的回归，已识别并纠正）
  5. `verify(timeout)` 观察到 insert 后 `drainScheduled` 复位存在不可观察窗口（tryEmit + 协程调度延迟）→ 第二次调用仍可能合并
- **修复**：两段式 + 轮询重试——先 `timeout(2_000)` 等第一次 insert，再用 `Mockito.mockingDetails` 计数 + 无 sleep 轮询重试第二次调用直到新周期启动（上限 2s）；最终 `timeout(2_000).times(2)` 断言 + captor 校验 mail id 幂等
- **验证**：连跑 3 次全绿

### 3.2 codegen 任务 Gradle/脚本双增量死锁（阶段 3.3 引入，已修复）

- **症状**：`generateSpriteAtlasDef` UP-TO-DATE 但 `SpriteAtlasDef.kt` 缺失 → `compileReleaseKotlin` 14 个 `Unresolved reference` 编译失败
- **根因链**：
  1. 脚本有内容 hash 增量（`.atlas-def.hash` 未变则跳过写文件）
  2. Gradle 执行前清理声明的 output 文件；hash 文件不在 outputs 声明内 → 清理删 kt 后脚本因 hash 匹配跳过 → 任务"成功"但产物缺失
  3. 下次判定：空快照 vs 空现状 → 永久 UP-TO-DATE 死锁
- **修复**：hash 文件纳入 outputs 声明（Gradle 清理连带删 hash → 脚本必重生成）+ `compileReleaseKotlin` 依赖生成任务（clean 后单独编译自动触发）
- **验证**：删产物重跑自动恢复；二跑 UP-TO-DATE 正常；`generateSpriteCode` 同类隐患一并修复
- **遗留说明**：kt 缺失→出现的跨状态变化对 Kotlin 增量编译是已知盲区（需一次非增量编译恢复快照），已记录
