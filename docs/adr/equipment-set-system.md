## 1. 背景

两股结构性问题在 2026-09 需求评审中合并立项：

1. **装备模型不可持续**：旧装备 = 4 槽位（含饰品）+ 72 个整件模板 + **数量堆叠轨**（`equipmentStacks`，`quantity>1`）+ 孕养度双源（弟子槽位与实例各存一份等级，穿卸/替换即漂移，D2）+ 三处价格口径不一（D5）+ 静态数据双表漂移（D1）+ codegen 非幂等（D9/D10）。堆叠语义与"词条/强化等级"这类**逐件差异属性**在模型上互斥——不可能在堆叠轨上表达"同 id 不同词条"。
2. **属性双列徒增维度**：物攻/法攻/物防/法防四列把"伤害类型"编码进基础属性，但游戏**没有出装二选一**（MOBA 拆双列的唯一动机，见方案 §15.1 Dota 2 反证），导致数值平衡要同时调 4 列、面板 4 行、而类型差异却没有清晰的承载点。

## 2. 决策一：属性单列（R12，EQ-B1）

**弟子/战斗体属性只有 `attack/defense` 两列；物法差异由三条类型通道承载**：普攻 `innateDamageType`（角色模板固定，首灵根派生）、技能 `damageType`、类型增伤/减伤分桶（默认 0.0 时与旧公式逐位一致，S19）。

**理由**：
- 类型由**角色与技能**决定而非出装决定——对标原神/星铁/Dota 2 的单列范式（方案 §15.1 对标表）；
- 迁移面可控：旧值回填 = 两列取和（k=1），战力公式线性恒等，迁移前后总战力逐位不变（S20 ∈ [0.98,1.02] 实测 = 1.0）；
- 数值平衡自由度收敛：调平衡从 4 列变 2 列，类型差异走乘区桶（`DamageZones.typeDamageBonus/Reduction`），与既有乘区法架构（architecture.md「Formula Architecture」）同构。

**替代方案（已否决）**：维持双列并新增"类型由技能决定"层——双列仍在但只剩"类型差异"一个用途，面板/迁移/平衡三面成本照付；一度摇摆回双列（方案 §13-14 决策轨迹在案），最终以 §15 单列为最终口径。

## 3. 决策二：删堆叠（R6，EQ-B3）

**装备禁用 `quantity>1` 语义**：一行一实例（`equipment_instances`），等级/经验/词条/强化次数全部随实例单点存储（`growth`）；堆叠轨（表/流/符号面）全链退役；实例**不设硬上限**（warn-only + 批量分解入口 + 不走溢出邮件）。

**理由**：
- 堆叠与逐件词条互斥——词条玩法（R7/R9/R10）的存在前提就是"每件不同"；
- 双轨并存（堆叠 + 实例）是 D2 孕养漂移的温床；单轨后"装卸不改等级"由存储模型结构性保证（R5，`EquipmentLevelPersistGuardTest`），不再依赖搬运代码正确；
- 无硬上限是拍板 #5：配套纪律（告警不截断 / 批量分解 / 溢出不发邮件）与 I10 触发条件（P95>1500 件）在案。

**替代方案（已否决）**：堆叠轨保留 + 词条实例化并存——两套语义长期并存等于 D2 永不闭合，且 ~497 文件引用面维持双分支；深度重构方案 §9 I1 已声明**无运行时开关**（两套存储语义并存的开关不存在），兜底 = 迁移前备份 + 云存档 + 强制更新。

## 5. 后果

**正向**：D1/D2/D4/D5/D6/D7/D9/D10 八项预存缺陷随重构一次清偿；类型差异获得清晰承载点；数值平衡维度减半；词条/洗练/套装的后续演进全部是**数据行级**扩展（方案 §8：套装 ×10 线性、洗练纯新增事务）。

**代价与登记**：
- 存档不可回退（I1）——更新公告与登录流程必须写明（文案见 report-B3 §8 / CHANGELOG 4.01.16 装备线节）；
- 速度/灵力体验面塌陷（R13）——维持不补偿拍板，监控建议（战斗回合数/闪避率分布）随 I9 族登记；
- 六项条件式遗留债 **EQ-I11~I16**（对拍两缺口桥端口 / 暴击面板 uncapped 评审 / 秘境旧堆叠轨 / TIER_DURATION 单位歧义 / AI 装备加成决策 / 结构性数值两条）——定义与触发条件见 `docs/architecture.md`「装备线遗留债登记」表，触发前不产生工作。

**热点缓存实测修正（记录在案，勿按方案字面翻案）**：`EquipStatResolver` 缓存采用**恒等键整解析**而非方案 §13-6 字面的"值语义缓存"——值语义键每调用 6 次全树深哈希，实测 6.3× 劣化（1286 ns vs 基线 242 ns）；恒等键 124–161 ns。版本安全性由 `EquipmentInstance` 全 val + copy 纪律保证（内容变必然新键）。
