# ADR：立绘精灵尺寸口径（建筑精灵 ≠ 占地，屏上不变形）

- 状态：已采纳（2026-09）
- 关联：`docs/design/topdown-view-art-spec.md`（美术操作手册）、`android/scripts/build-atlas.mjs`（尺寸源与构建期校验）、`android/core/engine/src/main/kotlin/.../render/BuildingRenderGeometry.kt`（底部对齐几何）

## Context（背景）

1. **素材是立绘，不是俯视平面图**：现役建筑素材为带高度的 3/4 立绘（巡视楼 569×1024、问道塔 439×658、青云塔 415×622、血炼池 1384×768…），而此前的渲染口径强制 `精灵尺寸 == 占地尺寸`（"1:1 贴地"，由两条守卫锁定）。
2. **后果——严重的画面变形**：立绘被硬压进正方形占地格。实测偏差：巡视楼 **+220%**（只显示出约 31% 的高度）、问道塔/青云塔 **+167%**、灵植阁/炼丹炉/藏经阁/执法堂/任务阁/监牢 **+78%**、血炼池 +26%。
3. **装饰同理**：4 草 3 石 2 树按"占 1 格 / 2 格的正方形"绘制，而素材纵横比各异（草 1.15、石 1.39、树 0.81），同样被压扁。
4. **地图投影存在纵向压缩**：`TOPDOWN_Y_SCALE = 0.75`（双端共享常量，模拟俯角；地面格在屏上呈 4:3）。竖向物体若按世界方形绘制，会再被压缩 25%。

## Decision（决策）

**立体素材（立绘建筑、草/石/树）按"屏上不变形"取值；俯视贴地素材按世界网格取值。**

| 类别 | 显示尺寸规则 | 理由 |
|---|---|---|
| 立体建筑（18 栋） | 精灵宽 `W = 占地宽`；精灵高 `H = round(W × 素材高 ÷ (0.75 × 素材宽))` | 除以 `TOPDOWN_Y_SCALE` 抵消地图纵向压缩 → 素材在屏上恢复原比例（2.5D 惯例：地面做透视压缩、竖向物体不压缩） |
| 俯视贴地（灵田；作物/瓦片/道路/岛边缘/门楼同理） | 世界纵横比 = 素材纵横比（与地格平铺对齐） | 必须与地格铺展一致，否则相邻格错缝 |
| 装饰（草/石/树） | 同上立体规则（小数格精度，树 2×3.291 格） | 同一口径，避免逐种类特判 |

**锚点契约（引擎既有几何，零改动）**

- 建筑：精灵底边对齐占地底边、水平居中（`offsetX = (fpW − sw)/2`、`offsetY = (fpH − sh)`）。
- 装饰：精灵底边对齐**自己格**的底边、水平居中（对象"站在"格子上）。
- 画家序键 = **地面接触点**（底边 Y）：立体层装饰（树）与建筑同序归并（`gamecore/map/draw_order.h`），同键时建筑在后（建筑压住同接触点装饰）。

**占地 = 建筑底座**：宽 = 精灵宽（左右不压盖）、深 = 底座进深（塔/亭 2 格、池 3 格、院落/山丘/殿保持现状）。占地**只减不增**——缩小不会让旧档建筑越界/重叠，读档 `fixupBuildingSizes` 自动改尺寸且不触发拆除退款。

**双层防线（防回归）**

1. 构建期：`build-atlas.mjs` `validateDisplaySizing` 对每栋建筑/每个装饰断言屏上纵横比 == 素材纵横比（容差 7% = 整数格取整残差上界），不满足即构建失败并打印应填尺寸。
2. 测试期：`SpriteSizingFidelityTest`（app）按 `atlas-manifest.json` 的 `srcW/srcH` 复核；`BuildingSpriteFootprintGuardTest` / `BuildingSpriteFootprintJsonGuardTest` 锁精灵/占地结构关系。

## Consequences（后果）

- **正向**：建筑/装饰恢复素材比例；塔类、楼阁重新"立起来"；放置预览框（占地矩形）与建筑底座对齐。
- **占用高度**：高精灵向北（上方）越出占地（巡视楼越界 8 格、天枢殿 6 格），按画家序正确遮挡其后方建筑与装饰；极端情况下小建筑（如灵田）可被前方塔完全遮住——属 2.5D 正常遮挡，若观感不可接受，回退旋钮 = 精灵高或占地深单点调整（守卫自动复算）。
- **装饰分层**：树移入立体层（与建筑同序），草/石留在跟随地面的地面层；两后端遍历范围按 `DECOR_MARGIN_COLS/ROWS` 外扩（否则 chunk 缝处树冠被裁）。
- **旧档兼容**：占地只减不增 → 无拆除、无挪位；天枢殿占地本批未动，且其**迁移判据已同批根治**（下节决策 3），从此天枢殿占地可安全调整。
- **图集**：槽位布局不变（仍需满足"槽位 ≤ 显示尺寸 × 4"），无需重排图集，仅 manifest 增加 `srcW/srcH`。
- **回退**：若要退回 1:1 贴地，只需还原配置尺寸并恢复旧守卫；渲染路径（底部对齐、命中区 = 占地 ∪ 精灵包围盒）本身与该口径无关。

## 后续决策（2026-09，用户拍板）

1. **接受"地面俯视 + 物体立绘"的素材视角混用（成本 0）**：实测 9 张装饰**没有一张是正上方俯视**——4 草 + 2 树为正面立绘、3 石为斜视 2.5D；地面/灵田/作物才是俯视。决定**不统一素材视角、不重画装饰**，按"地面俯视 + 物体立绘"混用口径继续（这也是本次尺寸改动的直接由来）。
2. **不降精灵高度**：塔类向上多占 6~8 格带来的遮挡（前方建筑遮住后方、北边界精灵越出岛界）维持现状，回退旋钮保留但不启用。
3. **天枢殿迁移判据根治**（原判据 = 「占地尺寸 ≠ 当前配置」）：改为**显式历史尺寸白名单** `TIANSHU_LEGACY_FOOTPRINTS = {6×3, 12×6}`——只有真实发布过的旧尺寸才走"删除 + 补偿 1000 万灵石"，其余尺寸（含现行配置与未来任何新尺寸）交给 `fixupBuildingSizes` 正常改写尺寸。守卫：`BuildingLoadSelfHealTest` 断言**现行配置尺寸绝不可落入白名单**（防地雷回归），`BootSequenceControllerTest` 增加端到端用例（非历史尺寸天枢殿零拆除）。
