# 规则：社交与排行规范

> ⚠️ **预留规范（未实现，约束未来设计）**：本文约束未来社交/排行扩展。现状基线：无好友/聊天/排行/分享，外交为纯 AI 模拟（`engine/domain/diplomacy/`）。见 `docs/knowledge-base.md#扩展性现状盘点`。

## 1. 核心原则（🔴）

1. **异步社交优先**（CoC "伪社交媒体"模式）：异步消息/离线可读/不要求同时在线——玩家搬家异地仍能一起玩；禁止设计强制同时在线才能完成的社交玩法
2. **社交独立模块，不污染 AI 外交路径**：好友/聊天/排行走隔离层（独立 Service/Store），**禁止修改 `engine/domain/diplomacy/` 既有 AI 外交代码**（好感度/结盟/附庸/进攻判定保持纯 AI 模拟）
3. **分层社交**：提供从轻量（点赞/看资料）到重度（组队/宗门协作）的不同层级选择，社交为可选而非强制（修仙玩家中有"独来独往闭关"型用户）
4. **社交价值闭环**：每次社交互动必须提供明确价值（物质奖励或情感满足），互惠设计（如互送体力/礼物），避免"为社交而社交"

## 2. 排行榜设计（🔴）

- **好友榜优先于全球榜**：玩家看到熟悉的名字更易产生追赶动力（行业实践：好友榜是最有效的排行榜类型）
- **分层奖励**：避免头部通吃——按百分位分层（Top1-10 / Top11-100 / 参与奖），让更多玩家有动力参与
- **赛季/周期重置**：软重置保留历史记录（跨赛季累计荣誉），给落后玩家"下一轮重新开始"的希望
- **动态目标**：显示与上一名/前 XX% 的差距（"再赢一场超过好友 A！"）
- **客户端不可信前提**：若引入服务端排行，数据必须签名/防重放校验，禁止客户端自报数据直接上榜；无服务端时只做本地榜（如宗门内部弟子战力榜）
- **排行榜维度**：多维度（战力/修炼/贡献/产量），单一战力榜易伤非战斗玩法玩家（玩家反馈：宗门排行榜应多维度化）

## 3. 数据合规（🔴）

- **最小化收集**：昵称/头像/UID 按需收集，禁止收集设备信息、真实身份信息
- **未成年人保护**：公开可见社交/排行默认关闭或需年龄判定（国内游戏合规要求）
- **PIPL/GDPR 对齐**：数据收集、存储、删除权利（注销账号时清理社交数据）完整流程
- **隐私政策双入口同步**：游戏内 `PrivacyConsentScreen.kt` + 网站版 `docs/index.html`（CLAUDE.md 设计方案原则 5）
- **反骚扰**：屏蔽/举报/黑名单机制，聊天内容过滤（脏词库或服务端审核）

## 4. 缓存与刷新（🟡）

- 排行榜/好友数据本地缓存 + 手动/定时刷新 + 失败重试**三态**（Loading / Error / Empty）
- 离线时展示上次快照，不空白（异步社交原则延伸）
- 数据走 ViewModel StateFlow + `showError()`，禁止 Composable 内直接发网络请求（rules/new-dialog-checklist.md 通用分组）

## 5. 分享（🟢 可选）

- 分享内容（境界/宗门/年度战报图）生成走**代码绘制**（Compose Canvas）或注册资源（rules/static-resources.md 动态内容规则）
- 文案模板统一（避免用户生成内容合规风险），分享跳转链接可追溯来源
