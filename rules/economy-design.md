# 规则：经济系统扩展规范

> ⚠️ **预留规范（未实现，约束未来设计）**：本文约束未来经济扩展（新货币/新资源/离线收益），当前仅灵石单一货币。现状基线（灵石源与汇初版清单）见 `docs/knowledge-base.md#扩展性现状盘点` 经济基线表——**每新增产出/消耗入口必须登记到该表**。

## 1. 新货币/新资源引入流程（🔴 硬性约束）

引入任何新货币（活动币/宗门贡献/荣誉点等）或新资源类型前，必须依次通过：

1. **必要性论证**：必须书面论证"为什么不能用灵石"——二级货币仅限活动币/宗门贡献类（限定期限或用途），禁止为单一玩法引入全局新货币
2. **闭环设计**：必须设计 **持有上限 + 获取源（≥1）+ 消耗汇（≥1）** 的完整闭环。**无汇不引入**——没有消耗出口的资源必然通胀贬值
3. **通胀防控三选一**（至少一项）：
   - **持有上限**（CoC 金库模式：存满后不消耗就无法继续获得；新货币限定使用范围）
   - **消耗池**（有吸引力的长期消耗出口，如商店兑换/升级消耗）
   - **炫耀性消费出口**（装饰/称号/限定外观类，解决"满级后无事可做"的摆锤衰减）
4. **奖励价值审计**："奖励越多价值越低"（Supercell 原则）——新奖励投放是否稀释既有货币价值？白名单 1000 万灵石邮件等大额投放必须评估对灵石价值锚的影响
5. **赛季化考虑**：活动货币按赛季限时 + 赛季结束清空或转化（AFK Journey 赛季制：解决"只做加法导致冗沉"）

## 2. 货币变更代码约束（🔴）

1. **存储变更**：新货币字段走完整 Migration（rules/database-migration.md 经济/货币字段变更流程）
2. **来源字典注册**：发放/消耗入口必须包裹 `withTrackingSource("来源名")`（来源名加入 `OverflowMailSender.SOURCE_DISPLAY_NAMES` 映射），年度报告与经济基线表可审计
3. **溢出语义类别判定**：凭据类（玩家可重试的领取——签到/兑换码/邮件）包 `withOverflowMailSuppressed`；发放类（自动入库——战斗/生产/交易）不包裹自动转邮件——选错类别导致货币重复发放或丢失（CLAUDE.md 13.3）
4. **发放入口统一**：走 `InventorySystem.addXxx` 统一入口 + `StackableItemStore` 合并（守卫测试 `InventoryAddPathGuardTest` 拦截手写合并）

## 3. 奖励投放准则（🟡）

- **"设计回收等于设计产出"**（Supercell）：规划任何产出前先回答"这些资源将如何回收、回收途径是否吸引人"
- **奖励额度登记**：发放来源 + 额度可审计（年度报告按来源拆分已有——`YearlyReport`）
- **慷慨原则**（CoC GDC 2020）：频繁慷慨优于吝啬——但慷慨额度必须与消耗出口匹配，否则加速通胀
- **不确定时做得难一点**：新系统数值不确定时，消耗设计从严（所有人都喜欢折扣，没有人喜欢加价）

## 4. 离线收益数学（🟡 预留）

未来引入离线收益（挂机产出）时：

- **收益比例**：挂机:活跃收益 ≈ 30%:70% 行业惯例区间（AFK 模式：离线经验 ~90%/金币 ~25% 因资源而异，产出效率型资源离线占比低、直接产出型占比高）
- **封顶机制**：挂机收益 12h 上限，强制每日 2 次回访（留存设计）；上限到期前推送提醒（需商业化推送频控——见 ad-cooldown.md 预留节）
- **接入点**：L0 时间推进结算（见 rules/expansion-playbook.md 离线收益预留），禁止另起结算循环
- **经济审计**：离线收益是纯新增源，必须配套新增消耗汇（第 1 条闭环设计）
