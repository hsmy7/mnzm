# 规则：经济系统扩展规范

> 本文约束经济扩展（新货币/新资源/离线收益）。当前在册货币：灵石（核心货币）+ 玉符（墙钟概念货币，豁免论证见 `docs/knowledge-base.md` 玉符节）。现状基线（灵石源与汇清单）见 `docs/knowledge-base.md#扩展性现状盘点` 经济基线表——**每新增产出/消耗入口必须登记到该表**。离线收益已于 2026-09-28 实时结算线 B7 落地（口径见本文 §4）。

## 1. 新货币/新资源引入流程（🔴 硬性约束）

引入任何新货币（活动币/宗门贡献/荣誉点等）或新资源类型前，必须依次通过：

1. **必要性论证**：必须书面论证"为什么不能用灵石"——二级货币仅限活动币/宗门贡献类（限定期限或用途），禁止为单一玩法引入全局新货币
2. **闭环设计**：必须设计 **持有上限 + 获取源（≥1）+ 消耗汇（≥1）** 的完整闭环。**无汇不引入**——没有消耗出口的资源必然通胀贬值
3. **通胀防控三选一**（至少一项）：
   - **持有上限**（CoC 金库模式：存满后不消耗就无法继续获得；新货币限定使用范围）
   - **消耗池**（有吸引力的长期消耗出口，如商店兑换/升级消耗）
   - **炫耀性消费出口**（装饰/称号/限定外观类，解决"满级后无事可做"的摆锤衰减）
4. **奖励价值审计**："奖励越多价值越低"（Supercell 原则）——新奖励投放是否稀释既有货币价值？白名单 1000 万灵石邮件等大额投放必须评估对灵石价值锚的影响
5. **赛季化考虑**：活动货币按赛季限时 + 赛季结束清空或转化（AFK Journey 赛季制：解决"只做加法导致冗沉"）

## 2. 货币变更代码约束（🔴）

1. **存储变更**：新货币字段走完整 Migration（rules/database-migration.md 经济/货币字段变更流程）
2. **来源字典注册**：发放/消耗入口必须包裹 `withTrackingSource("来源名")`（来源名加入 `OverflowMailSender.SOURCE_DISPLAY_NAMES` 映射），年度报告与经济基线表可审计
3. **溢出语义类别判定**：凭据类（玩家可重试的领取——签到/兑换码/邮件）包 `withOverflowMailSuppressed`；发放类（自动入库——战斗/生产/交易）不包裹自动转邮件——选错类别导致货币重复发放或丢失（rules/pr-review-checklist.md）
4. **发放入口统一**：走 `InventorySystem.addXxx` 统一入口 + `StackableItemStore` 合并（守卫测试 `InventoryAddPathGuardTest` 拦截手写合并）

## 3. 奖励投放准则（🟡）

- **"设计回收等于设计产出"**（Supercell）：规划任何产出前先回答"这些资源将如何回收、回收途径是否吸引人"
- **奖励额度登记**：发放来源 + 额度可审计（年度报告按来源拆分已有——`YearlyReport`）
- **慷慨原则**（CoC GDC 2020）：频繁慷慨优于吝啬——但慷慨额度必须与消耗出口匹配，否则加速通胀
- **不确定时做得难一点**：新系统数值不确定时，消耗设计从严（所有人都喜欢折扣，没有人喜欢加价）

## 4. 离线收益数学（✅ 已定稿，2026-09-28 实时结算线 B7 落地）

**口径（方案 §1.4 已拍板，唯一折算入口 = `GameConfig.Time.offlineGameMs`，core/domain 纯函数整数运算）**：

- **时段计量**：离线时段 = `lastSaveTime`（现实墙钟基）→ 本次读档墙钟差；速率与在线速度档解耦（离线恒按 1x 换算）——防"杀进程挂机/高速档挂机"成为最优策略
- **分段折算**：≤12 现实小时全额 → 12–24h 段按 50%（整数分子制 1/2）→ 24h 硬顶，超出不再累积；注入总量上限 = 12h + 12h/2 = **18h 游戏时间**（64_800_000 游戏毫秒）
- **网格与防御**：结果 floor 到旬（2000 游戏毫秒整数倍，保持权威轴旬网格对齐）；负输入/零（时钟回拨）按 0
- **收益内容边界**：离线只重放**连续积分项**（L1 HP/MP 恢复/修炼/熟练度/孕养 + 月度连续项政策月费/丹药衰减/灵矿毫秒差分）；**判定轨 0 次、月年离散事件 0 次、RNG 零消耗**——突破/战斗/任务等需玩家在场的判定不在离线发生，离线:活跃收益比由封顶自然形成，不另设比例参数
- **接入点**：读档时 `GameEngineCoreOfflineOps` 两段式注入 → C++ `GameCore::injectOfflineGameMs`（线程契约见 `docs/threading-contract.md` 表四）；**禁止另起结算循环**——新离线产出项挂进 `accrueContinuous`/`accrueMonthlyContinuous` 积分函数族即自动被离线复算
- **留存设计**：12h 全额上限保留"强制每日回访"节奏（AFK 行业惯例）；12h/24h/50% 为首版经验值，上线 2 周后按实际 D1/D7 与产出分布复盘校准（方案风险表 D4）
- **经济审计**：离线收益是纯新增源——折算口径改动必须复跑"一次性注入 ≡ 分帧积分"经济总量对拍（`OfflineInjectionTest` 逐位一致基准）；新增离线产出项必须登记 `docs/knowledge-base.md` 经济基线表并过第 1 条闭环设计
