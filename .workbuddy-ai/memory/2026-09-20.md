## B15 / R6.1 图集离线化（消运行时 Canvas 拼装，运行时只 upload）

**用户指令**：读 `docs/parallel-batches-w5/batch-R6A.md`，严格实施 B15，按文件内验收门
自检并出报告。批次身份三重确认：**B15 = R6.1 = `batch-R6A.md`**（文件名 ≠ 批次号）。

### 核心结论

B15 前三条支路（Canvas 软渲 / RGBA 回退臂 / RGBA mip 链）共用
`SectAtlasAssembler.buildAtlasBitmap` —— **启动期在设备上**逐精灵
`BitmapFactory.decodeResource` + `Canvas.drawBitmap` 拼 2048² ARGB_8888 位图。
本批把「像素来源」整体搬到**构建期**，运行时只做一次性解码/映射 + upload。

### 关键技术决策（可复用）

1. **产物形态 = 裸像素 RAW + JSON 清单**（非 PNG）：只有 RAW 能 `FileChannel.map`
   **零拷贝**（不占 Java heap、不 decode）且软渲臂可一次 `copyPixelsFromBuffer`
   （直通 alpha RGBA8888 与小端 ARGB_8888 **逐字节等值 ⇒ 无需 swizzle**）。
   代价 = 37.33 MiB 入库资产，换启动期 heap 峰值 53.26 MiB → 0 / 33.26 → 16 MiB。
2. **同源架构**：产物由 `build-atlas.mjs` 的 `main()` **内联**产出，复用 ASTC 图集
   同一份 `contents`；把「源 → 预乘 → lanczos3 槽位」抽为共享
   `lib/atlas-offline-rgba-lib.mjs::loadPremultipliedRgba` ⇒
   「两条图集路径精灵内容同源」成为**结构事实**而非比对断言。这是本批最重要的架构手法。
3. **`SectAtlasAssembler` 退役形态 = 「类本体转测试夹具」（非删除）**：因为
   `downscaleWithBilinearChain` 是 `SoftwareCanvasBackend.drawPreScaled`（红线路径）的
   **单一实现**，`buildingAtlasDrawableMap`/`tileDrawableRes` 是既有守卫测试入口。
   338 → 111 行，只删拼装路径。

### 像素重采样核实测（重要经验，跨批复用）

**结论：无任何重采样核能与 Skia 双线性逐位对齐。** 四组候选实测（源 → 槽位半尺寸）：

| 配方 | 超阈值（>8/255）占比 |
|---|---|
| `lanczos3`（产物所发） | 4.68% – 12.50% |
| `linear`（双线性同核） | 4.68% – 12.50% |
| 链式减半（双线性分步） | 10.47% – 26.50% |
| 精确区域平均（box） | 3.59% – 24.00% |

⇒ **等价性守卫必须四层口径**：硬门 = 结构等价 + golden 校验和 +
「按产物真实生产链的确定性逐位复现」；软门 = 消费面容差对照（阈值基于实测分布，
并显式登记为「守卫退化」而非「证明等价」）。

**坑 1**：链式缩放与单步缩放**不等价**。产物是两段（`源→槽位→半槽位`，因复用
ASTC 图集 contents），运行时拼装是单步。任何「源 → 半槽位」单步重建都与产物逐位不符
（GRASS1 maxDiff=255）⇒ 不能假定缩放可合并。
**坑 2**：等价性守卫的「运行时配方」**必须走预乘空间**再缩放（再解预乘），否则透明区
未定义颜色参与插值 ⇒ maxDiff=255 假阳性（GRASS1 16.5%）。

### 其它踩坑

- **Gradle 隐式依赖**：任务读了 `:core:engine` 的 output（`SpriteAtlasDef.kt`）必须
  显式 `dependsOn ':core:engine:generateSpriteAtlasDef'`，否则报
  `implicit dependency` 配置错误。
- **静态门禁必须先去注释**：退役后 KDoc「历史落点」段会刻意提及旧函数名 ⇒
  直接扫全文**假红**。剥离 `/* */` 与 `//`（保留字符串字面量与 `"""`）后扫描。
- **Gradle 单元测试工作目录 = `android/feature`（不是 `android/feature/game`）**：
  仓库既有 `EdgeKtxSyncTest` 用 `../../app/...` 即是佐证。定位仓库文件按此基准，
  并兜底两级。
- **`FileChannel.map` 返回的 ByteBuffer 默认 `BIG_ENDIAN`**（JDK 规范，与
  `allocateDirect().order(nativeOrder())` 不同）。裸像素按字节消费，测试不应断言
  `nativeOrder()`。
- **产物 manifest 的 sprites 只有 `name/sha256/bytes`**（无 x/y/w/h）——落位几何
  应由 `SpriteAtlasDef` 权威**推导**（`round(x*0.5)` / `slot>>1`），不要往 manifest
  塞冗余几何。
- **Gradle 并行门互斥**：组合门跑着时另起 Gradle 命令会撞
  `journal-1.lock（拒绝访问）`；须等门结束或 `gradlew --stop`。
- **`mergeReleaseResources` Windows 文件锁**：实测在组合门第二次重跑时触发
  （`Unable to delete directory ... merged_res\release\mergeReleaseResources`）。
  处置口径 = `gradlew.bat --stop` + `rm -rf app/build/intermediates/merged_res/release/mergeReleaseResources`
  + 清 `~/.gradle/caches/journal-1/journal-1.lock` 后重跑，**勿改代码**。
- **detekt 打回两轮，都是「重构引入的残留」**：第一轮 `stripKotlinComments` 复杂度
  （CyclomaticComplexity 28 > 15 / NestedBlockDepth / ComplexCondition），拆小函数后过；
  第二轮 `NativeSurfaceViewTest.offlineAtlasSpecOrNull(ctx)` 的 `ctx` 参数在路径 helper
  重构后**不再被使用** ⇒ `UnusedParameter`。教训：**重构成 helper 后要顺手检查参数表**，
  否则 detekt 会在全量门末尾才打回（约 48 min 后）。
- **全量组合门实测耗时 ≈ 48 min**（233 tasks 全 executed），比批次文件预估的 20–35 min
  长；各阶段实测：编译 ~30 min → 测试 ~12 min → detekt/lint 尾段 ~5 min。规划时按 50 min 预留。
- **检测 XML 汇总的「假新鲜」陷阱**：`build/test-results/` 下同时存在
  `testDebugUnitTest`（历史）与 `testReleaseUnitTest`（本轮）两种目录；且**过滤 run**
  （`--tests`）只重写被选中类的 XML，其余保留旧文件。⇒ 汇总脚本必须（a）只收
  `testReleaseUnitTest*` 目录，（b）打印 XML mtime 范围并做陈旧告警。
  已固化为 `android/scripts/summarize-junit-xml.py`（支持 `--json`）。
- **测试类名前缀过滤要看 `classname` 而非 `name`**：Gradle XML 的 `testsuite/@name`
  与 `testcase/@classname` 都是 FQCN；按「简单类名前缀」过滤须先 `rsplit('.', 1)`。
